# Idiomas y monedas (i18n)

## Cómo se elige al primer ingreso
- **Idioma** (`src/i18n/detect.ts → getInitialLanguage`): `?lang=` en la URL → elección guardada (`localStorage.crt_language`) → primer idioma habilitado de `navigator.languages` (ES si es español) → **EN** para el resto.
- **Moneda** (`getInitialCurrency`): elección guardada (`crt_currency`) → región del navegador: zona horaria `America/Costa_Rica` o `xx-CR` → **CRC**; país de la eurozona (o zona horaria europea del euro) → **EUR**; resto → **USD**.
- Solo se guarda lo que el usuario elige en los selectores (App.tsx envuelve `setLanguage`/`setCurrency`). La detección nunca se escribe en `localStorage`.

## Textos
- Un solo punto de entrada: `createT(language)` / `translate(language, key, vars)` de `src/i18n`.
- Catálogos: `src/i18n/messages/es.ts` (define las claves) y `en.ts` (tipado `Messages`: el type-check falla si falta una clave).
- Claves planas con espacio de nombres: `footer.*`, `toursGrid.*`, `tourCard.*`. Variables `{nombre}`.
- `translate` cae a la tabla antigua `UI_TRANSLATIONS` (src/utils/i18n.ts), así que los componentes pueden migrar poco a poco. No agregar ternarios `language === 'es' ? … : …` nuevos.
- Migrados: Footer, filtros/catálogo (ToursGrid) y fichas (TourCard). Pendientes: ver "Qué falta".

## Añadir PT / FR / DE
1. `src/types.ts`: añadir el código a `Language` (`'pt'`). Si se añade `pt`, cambiar `UI_TRANSLATIONS` a `Record<string, Partial<Record<Language,string>> & { es: string; en: string }>` y `ecoFacts.ts` (usan `Record<Language,string>`).
2. `src/i18n/locales.ts`: entrada con `bcp47`, `ogLocale`, `flag`, `enabled: false`.
3. `src/i18n/messages/pt.ts`: `export const pt: Partial<Messages> = { … }` (lo que falte cae a EN) y registrarlo en `CATALOGS` de `src/i18n/index.ts`.
4. Cuando la UI esté completa: `enabled: true`. Aparece solo en el selector, en la detección y en hreflang. Actualizar `tests/uxTrustAudit.contract.test.ts` (espera `['es','en']`).

## SEO
- `RouteMetadata` fija `<html lang>`, `og:locale`, canonical y `<link rel="alternate" hreflang>` (`es`, `en` con `?lang=`, `x-default` sin parámetro). `index.html` trae los mismos para la portada.

## Qué falta (migración gradual)
- Quedan ~1.500 ternarios `es ? … : …` en otros componentes (mapa, transporte, asistente IA, modales de reserva, admin). No mezclan idiomas, pero no salen del catálogo: migrar por componente con el mismo patrón (`createT`).
- Header: lo simplifica otro agente; sus textos siguen en `UI_TRANSLATIONS`/ternarios (p. ej. `aria-label` "Ver mis reservas" vs. texto visible "Reservas").
- Sitemap sin `xhtml:link` hreflang (el contenido es el mismo por ruta; se puede añadir en `scripts/generateSitemap.ts`).
